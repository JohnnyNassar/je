“Cover logo” edits now show online

•
Reported issue
A Cover-logo save looked successful but the change never appeared on the live product page.
Diagnosed
•
Root cause
The save worked — the file was written and served correctly. nginx caches /storage images as immutable, so browsers kept showing the stale copy at the same URL.
Found
•
Fix shipped
Added a ?v=<file-mtime> cache-buster across all storefront image URLs so an in-place edit changes the URL and defeats the cache; hardened the controller against silent write failures.
Deployed
•
Verified on production
Confirmed product 91 now renders a versioned URL serving the covered image. Commits 4d1488a + 9373d24.
Verified

Product videos

•
Two roles, not one
Short clips = muted autoplay loop in the gallery (self-host on the VPS). Long videos = poster + tap-to-play (self-host if low volume, else a managed CDN like Bunny / Cloudflare Stream).
Proposed
•
Real constraint = bandwidth, not storage
140 GB free, so storing is easy. Serving long video from the single VPS pipe (no adaptive bitrate) is the limit a CDN solves later.
Proposed
•
Build (~1 day for v1)
Install ffmpeg, raise upload limits + chunked uploads, videos JSON field, Filament upload + transcode/poster, storefront players.
Proposed
Decisions needed from client
  • Confirm short-autoplay / long-tap-to-play split.
  • One video per product, or several?
  • Clip-vs-long by admin toggle, or auto-detected by duration?
  • Expected volume & who uploads.
